# PCinema 1.2.0 — проверка 23 октября 2026

## Подтверждено в этой версии

- 53 автоматических теста проходят, Release / win-x64 self-contained собирается без предупреждений. Новые тесты покрывают объединение относительных перемоток, отмену ожидающих команд, FIFO после ошибки, ожидание записи при закрытии, занятую SQLite и защиту новой позиции от устаревшего снимка.
- Каталог с 10 000 реальными однобайтовыми файлами и предварительно заполненной базой: повторная сверка без дубликатов; имитация недоступного источника сохраняет все записи. Это тест каталогизации, не декодирования 10 000 видео и не измерение задержки WPF на такой библиотеке.
- История: удалённые файлы и исключённые источники доступны через историю, точная позиция сохраняется; в списке истории отображаются только тайтл, сезон, серия и состояние. Отдельно проверен настоящий UI: переход к архивному тайтлу без файлов, сохранённое описание, отключённая кнопка воспроизведения.
- Сравнение с TMDB: запрашиваются все сезоны, включая отсутствующие локально; повторные файлы одной серии не увеличивают покрытие. Будущие серии, неизвестная дата, спецвыпуски и недоступные файлы проверены тестами. Частичный сетевой сбой не затирает ранее сохранённый полный список. UI офлайн-сравнения проверен на контролируемом кэше.
- В настоящем WPF-плеере проверены воспроизведение H.264, одиночная пауза мышью, перетаскивание на паузе с обновлением картинки, двойной щелчок с сохранением паузы, выход из полного экрана с восстановлением размера, автопереход E01 → E02 и штатное закрытие.
- Диагностика ограничена тремя файлами по ~2 МиБ. Журнал содержит этапы, длительности и типы исключений, без токенов, названий и полных путей. Старый неограниченный errors.log больше не записывается. Ничего автоматически не отправляется.

Кэш плагинов генерируется **при сборке поставки**, по [рекомендации VideoLAN](https://docs.videolan.me/libvlcsharp/docs/best_practices.html); пользователь не должен ждать его генерации. При смене LibVLC кэш пересобирается. Обычное сканирование плагинов не отключалось.

## Воспроизводимый стенд

`tools/PerformanceProbe` принимает пути к видео, открывает каждый файл три раза в каждом режиме и выполняет 30 перемоток вперёд/назад, включая 10 на паузе. Проверяет достижение позиции и сохранение паузы, а при открытии — счётчик отображённых кадров. Вывод содержит индексы файлов, без их путей.

```powershell
dotnet run --project tools/PerformanceProbe -c Release -- "sample-h264.mp4" "sample-h264.mkv" "sample-hevc.mkv" "sample-hevc.mp4"
```

Итоговый последовательный прогон: **240 из 240 перемоток прошли**, по 30 для H.264 MP4/MKV и HEVC MP4/MKV в каждом из двух режимов; 80 проверок сохранения паузы, кадр получен во всех 24 открытиях. Один предыдущий запуск одновременно со сборкой завершился кодом 1 без вывода; причина не установлена, итоговые числа взяты из отдельного последовательного повторного запуска.

Стенд использует `--vout=dummy --aout=dummy`: успешный результат **не доказывает отсутствие зависшего изображения на D3D/GPU**. Он проверяет команды, декодирование и временную шкалу. Результаты локально: `artifacts/session-performance-final.json`.

Установщик: `artifacts/PCinema-Setup-1.2.0.exe`, 75 320 772 байт. SHA-256: `9BB9C0ADBC2677D119469840F69F801E5362B1738F1CB76ED820A8C48BAF25E6`.

## Неподтверждённые цели и ограничения

- Холодный запуск после перезагрузки не измерен. Не выдаём запуск нового процесса с прогретым диском за этот сценарий.
- p95 визуального отклика ≤100 мс не подтверждён. В диагностике присутствовал стартовый скачок диспетчера ~314 мс и отдельные задержки 65–81 мс; это не замер input-to-render.
- Условная цель ускорения повторного открытия на 30% при исходном времени >1 секунды неприменима к использованному образцу: исходная медиана ~655 мс. На тяжёлых пользовательских файлах сравнение ещё необходимо.
- Полная матрица из 30 визуально наблюдаемых перемоток через D3D на H.264/HEVC в обоих режимах, горячая смена декодера/дорожек, принудительное завершение процесса, DPI 150/200% и чистая Windows 11 без .NET/VLC в этой итерации не проверены. Автоматические тесты и dummy-стенд их не заменяют.
- Проверка занятой базы и 10 000 файлов подтверждает фоновую обработку и сохранность данных, но не устанавливает p95 UI под этой нагрузкой.
- Реальный API TMDB для новой проверки всех сезонов не вызывался: HTTP-ответы проверены контролируемым обработчиком; UI — с кэшированным списком и отключённой сетью TMDB.
- Установщик использует прежний AppId и пользовательский каталог установки; схема базы остаётся v3, новые данные находятся в settings. Проверка обновления на отдельной чистой VM не проводилась.
- Исходники не содержат TMDB-токена; локальная поставка использует ранее разрешённый пользователем закрытый ресурс `.secrets/tmdb.token`. GitHub не обновлялся.

## Оптимизации

- Строки каталога виртуализируются и переиспользуются; главный экран ограничивает число карточек.
- Поиск применяется после задержки 160 мс, без сетевых запросов.
- База читается и папки сканируются вне UI-потока; группы эпизодов собираются через lookup вместо повторного обхода всех эпизодов.
- SQLite индексирует series_id. Сканирование записывает только изменившуюся доступность файлов.
- Изображения декодируются с ограничением размера, кэшируются с освобождением неиспользуемых изображений; основные изображения предварительно загружаются в фоне.
- Переходы и наведения анимируют прозрачность и масштаб, а не геометрию интерфейса.
- Автосопоставление не запускается одновременно несколько раз; повторный неуспешный поиск ограничен 30 минутами в рамках сеанса; для 429 предусмотрены ограниченные повторы.

## Границы проверки

- Это проверка на текущем Windows-компьютере, а не на чистой виртуальной машине без SDK/VLC. Сборка опубликована self-contained и включает LibVLC.
- Не завершена отдельная матрица Windows DPI 100%, 150%, 200% и нескольких мониторов.
- Нет измерений FPS и задержек на большой реальной библиотеке или слабом ПК. Перечисленные оптимизации реализованы, но обещание конкретной частоты кадров не делается.
- Визуальная компоновка и элементы адаптированы по Cinejoy; пиксельная идентичность сайта не заявляется. Русские подписи, локальная библиотека и функции Windows создают намеренные отличия.
- В этой итерации принудительное завершение процесса и внешние SRT/ASS не проверялись вручную повторно. Механизм сохранения каждые 5 секунд сохранён; тесты хранилища проходят.
- Сертификат издателя отсутствует. В версии 1.0 наблюдалась блокировка Windows Application Control; в проверенной сборке 1.1 на текущем компьютере она не воспроизвелась.
