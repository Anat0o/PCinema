# Модули PCinema 1.0 / API 1

Модули устанавливаются локально: **Модули → Установить из файла → .pcmodule → Включить**. Для программных модулей и рескинов нажмите «Перезапустить». Тема и шрифт меняются сразу. Кнопка «Модули» в заголовке и Ctrl+Shift+M открывают встроенный менеджер независимо от рескина. Escape возвращает назад; в плеере сначала закрывает панель/полный экран/PiP.

## Примеры

- `pcinema.compact`: боковая навигация, плотные списки библиотеки/истории/серий, другая панель управления видео. «Все действия и стандартный вид» раскрывает встроенные инструменты. В PiP используются компактные элементы ядра.
- `pcinema.pt-sans`: PT Sans с кириллицей, без кода. Не меняет иконочные шрифты и настройки субтитров. Оригинальный файл [Google Fonts / ParaType](https://github.com/google/fonts/tree/main/ofl/ptsans) распространяется без изменений с OFL 1.1 (`examples/Font/OFL.txt`).
- `pcinema.sleep-timer`: «Расширения → Таймер сна», 1–720 минут; по истечении ставит плеер на паузу. Есть страница настроек и команды в меню сериала/серии. Таймер не переживает завершение приложения; выбранное число минут сохраняется.

Сборка всех примеров: `./build-modules.ps1`. Результаты находятся в `artifacts/modules`. Проекты примеров ссылаются только на SDK, не на основной проект.

## Доверие и восстановление

Feature и Skin — доверенный код с правами PCinema, **не песочница**. Возможности в манифесте только описывают назначение. Такой код может читать файлы, обращаться к сети, зависнуть или завершить весь процесс. Отдельный AssemblyLoadContext разделяет зависимости, но не является защитной границей. Устанавливайте код только от доверенных авторов.

При ошибке запуска модуль не регистрируется на текущий сеанс; ошибка видна в менеджере. После аварии приложение предлагает встроенный интерфейс до загрузки расширений. Полностью завершите PCinema и запустите `PCinema.exe --safe-mode`, чтобы вручную включить безопасный режим. В нём можно отключить или удалить проблемный пакет. Обычный запуск восстанавливает выбранные расширения.

Обновление: установите тот же ID с новой версией. Предыдущая версия остаётся для кнопки «Откатить». Для кода откат/удаление/включение вступают в силу после перезапуска. Удаление сохраняет данные; «Очистить данные» очищает их при следующем запуске. Библиотека и история не затрагиваются.

Хранилище: `%LocalAppData%/PCinema/Modules/{packages,data,staging}`, отдельный `registry.json`. Установка проверяет архив и распаковывает во временную папку, затем меняет реестр атомарно. Данные модуля находятся в `data/<id>` и сохраняются при обновлениях. Не изменяйте содержимое установленной версии вручную.

## SDK и шаблон

Нужны Windows и .NET 10 SDK. Скопируйте `templates/Module`, укажите собственные ID/имя/автора/версию и лицензию. Ссылка проекта должна вести на `PCinema.ModuleApi.dll` из SDK; сборку SDK не кладите в пакет.

```powershell
dotnet build Module.csproj -c Release -p:SdkPath=C:/SDK/PCinema.ModuleApi.dll
./pack.ps1 -SdkPath C:/SDK/PCinema.ModuleApi.dll
```

`IPCinemaModule` имеет открытый конструктор без параметров. `Register` быстро регистрирует определения в UI-потоке; не выполняйте там I/O. `StartAsync` вызывается в рабочем потоке после появления главного окна, должен вернуть управление за 15 секунд. Фоновая задача должна отслеживать переданный токен. При выключении вызывается `StopAsync` с ограничением 5 секунд. Остановите и дождитесь своих задач, освободите подписки. Страницы создаются лениво в UI-потоке. Представление может повторно загружаться при «Назад»: подписки/таймеры страницы запускайте в Loaded и освобождайте в Unloaded.

`IModuleRegistration`: AddPage (IsSettings для настроек), AddSeriesCommand, AddEpisodeCommand, SetSkin. Команды получают стабильные ID сериала/серии. Фоновые службы принадлежат жизненному циклу самого модуля. Зависимости между сторонними модулями в API 1 отсутствуют.

### Контекст

| API | Назначение |
|---|---|
| GetLibraryAsync / GetHistoryAsync | Снимки SeriesInfo/EpisodeInfo; история включает недоступные тайтлы |
| NavigateAsync / OpenPageAsync / GoBackAsync | Основные маршруты и собственные страницы в том же окне |
| PlayAsync / SetPausedAsync / SeekAsync | Команды ядру; позиция и длительность в миллисекундах |
| NextEpisodeAsync / SetVolumeAsync | Следующая доступная серия и громкость 0–100 |
| Player | Неизменяемый последний снимок, EpisodeId=null вне плеера |
| ToggleFullscreenAsync / TogglePictureInPictureAsync / ShowPlayerOptionsAsync | Полный экран, PiP и встроенный выбор дорожек |
| ReadSettingAsync / WriteSettingAsync | Собственные строковые настройки, null удаляет значение |
| DataDirectory | Каталог собственных файлов модуля |
| Subscribe | IDisposable-подписка на события, обработчик должен быстро возвращаться |
| OnUIAsync | Короткие операции с WPF в UI-потоке |
| Log | Локальная диагностика: короткие машинные коды событий, без секретов/путей |

События: `library.changed`, `playback.opened`, `playback.playing`, `playback.paused`, `playback.closed`. Вызовы навигации/плеера маршалятся на UI-поток, а VLC-команды выполняются существующей очередью. Завершение SDK-команды означает передачу ядру, а не подтверждение показанного кадра. После StopAsync контекст больше не используется. Обработчики собственных async UI-событий должны перехватывать исключения и вызывать Log.

DTO не дают доступа к SQLite, токену TMDB, MainWindow, путям видео или нативному VLC. ID нельзя пересоздавать из пути файла. Числа Season/Number могут быть null. UI и плагины не записывают прогресс напрямую: это ответственность ядра.

### Рескины

Skin регистрирует `IModuleSkin`. `CreateShell(ShellContext)` размещает переданный Content ровно один раз; `CreateView(ViewContext)` возвращает WPF-представление Home/Library/History/Series/Player. Состояние берётся из DTO/Player через Host. BuiltInView — готовое представление ядра, которое можно вернуть или встроить как резервное. Не меняйте его DataContext и не приводите к внутренним типам PCinema.

Для Player заменяется **только слой управления над видео**. Управляемая ядром видеоповерхность, единственный движок, горячие клавиши и запись истории остаются в ядре. Не создавайте VideoView/LibVLC. Менеджер модулей, аварийное восстановление и оконная рамка всегда встроенные. Не храните WPF-элементы между разными экземплярами страниц и не добавляйте один элемент к двум родителям.

### Оформление

Приоритет: встроенные значения → ThemeTokens рескина → активная тема → шрифт. Один активный Skin/Theme/Font, несколько Feature. Используйте SetResourceReference или DynamicResource, чтобы обновления темы и шрифта применялись сразу. Стандартные контроли наследуют шрифт, но явное значение FontFamily его перекроет.

| Ключ | Тип JSON / значение |
|---|---|
| App.Background, App.Panel, App.Text, App.Muted, App.Accent | строка `#RRGGBB` или `#AARRGGBB` |
| App.FontSize | строковое число 10–64 DIP |
| App.Radius | строковое число 0–64 DIP |
| App.Animation | строковое число 0–1500 мс, появление страниц |

`App.Font` — FontFamily, устанавливается пакетом шрифта, не JSON-темой. Иконки и субтитры независимы. Семантические ресурсы покрывают базовую палитру/контроли; фотографии, затемнение видео и специальные состояния имеют собственное оформление. Рескин может полностью определять свои представления.

## Формат .pcmodule

ZIP без внешней папки: manifest.json, сборки/ресурсы и лицензии. JSON нечувствителен к регистру имён полей. ID — строчные латинские сегменты с точками/дефисами; версия — три числа. API 1 принимает только apiVersion=1.

```json
{
  "id": "example.my-module", "name": "My module", "author": "Author",
  "version": "1.0.0", "kind": "Feature", "apiVersion": 1,
  "entryAssembly": "MyModule.dll", "entryType": "MyModule.Module",
  "capabilities": ["Дополнительная страница"]
}
```

Skin использует такую же точку входа. Для Theme замените kind на Theme и добавьте `themeFile: "theme.json"`; для Font — `fontFile: "font.ttf"`, `fontFamily: "Family Name"`. В пакетах оформления разрешены только JSON, TTF/OTF, PNG/JPEG и текст лицензий; произвольного XAML/кода нет. DLL-зависимости размещайте рядом с entryAssembly в корне пакета; API загружается совместно с приложением. Не включайте системные WPF/.NET-сборки. Native DLL должны быть x64. Максимум: 4096 элементов, 150 МиБ на файл, 512 МиБ распакованного содержимого. Абсолютные пути, `..`, ссылки и повторяющиеся пути запрещены.

VPN-драйверы, службы, повышение привилегий, автообновления, взаимные зависимости и онлайн-каталог не входят в API 1. VPN или торрент-функции могут быть отдельными доверенными модулями с собственными зависимостями, страницами и фоновыми задачами.


## SDK 1.1: настройки и синхронизация

Менеджер находится в **Настройки → Модули**. `Route.Modules` и Ctrl+Shift+M перенаправляются туда. Страницы с `IsSettings=true` открываются внутри настроек конкретного модуля; остальные страницы — кнопками открытия в карточках модулей. AssemblyVersion SDK остаётся 1.0.0.0 для двоичной совместимости; версия поставки — 1.1.0.

Необязательный `IPortableModuleSettings` объявляет `PortableSettingsVersion` (>0) и `PortableSettingKeys`. Без этого контракта настройки целиком локальные. Ключи: 1–128 символов A–Z, a–z, 0–9, `_`, `.`, `-`. Версия является пространством имён схемы; несовместимую версию увеличивайте. Не объявляйте переносимыми секреты, пути, активные задания и настройки, привязанные к устройству.

После применения облачных значений модуль получает `AppEvent("settings.synced")` через обычную освобождаемую подписку. Перечитайте объявленные ключи через `ReadSettingAsync`; обработчик не должен выполнять долгую работу в UI-потоке. Пример SleepTimer переносит только `minutes`; активный отсчёт не переносится. Для отсутствующего модуля значения сохраняются до ручной установки и запуска совместимого пакета.


## Ресурсы «Тёмного стекла»

SDK предоставляет дополнительные необязательные ключи `ThemeKeys.Glass`, `ThemeKeys.Border`, `ThemeKeys.Hover`. Значения по умолчанию — `#EB171B24`, `#24FFFFFF`, `#16FFFFFF`. Старые темы не обязаны объявлять эти ключи. Существующие ключи и AssemblyVersion SDK сохранены. Пакет шрифта применяется поверх встроенного шрифта; иконочные шрифты и субтитры остаются независимыми.
