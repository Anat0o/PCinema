# Синхронизация PCinema 1.0

`GoogleAccount` отвечает за OAuth/PKCE и DPAPI. `GoogleDriveTransport` передаёт снимки через Drive v3 appDataFolder. `SyncCoordinator` объединяет версии, проверяет поколение и применяет записи. `SyncService` планирует обмен и обновляет состояние страницы аккаунта. Сеть не входит в очередь локального сохранения прогресса.

Формат 1: `SyncDocument(Schema, Generation, GenerationStamp, Device, Entries)`. Запись: `Key`, JSON/string `Value`, `Stamp(Milliseconds, Counter, Device)`, `Deleted`. Снимок каждой установки хранится отдельно; дубликаты ответа безопасны благодаря детерминированному объединению. Неизвестный формат и некорректные данные блокируют отправку. Установка ограничивает размер входящих снимков и число записей.

Переносимые пространства ключей: `history:`, `alias:`, `setting:` (строгий список), `module:`, `module-setting:<ID>:<schema>:<key>`. История содержит минимальные текстовые метаданные, TMDB/UUID и прогресс. UUID не объединяются по названию. Алиасы сохраняют ручное сопоставление с TMDB. Tombstone имеет приоритет при равной версии. Все изменения, включая сброс позиции, используют один порядок версий.

В SQLite добавлены `sync_records`, `sync_identity`, `sync_meta`, `sync_setting_versions`. `sync_records` вместе с флагом pending является устойчивой очередью: полный снимок не требует удаления событий после каждого HTTP-запроса. ID старых серий и история сохраняются. Миграция добавочных таблиц транзакционна; до неё SQLite Backup API сохраняет согласованную копию в `backups`. Версия основной схемы истории остаётся 3; таблицы синхронизации проверяются отдельно.

`installation.id` создаётся отдельно от базы и не синхронизируется. Его нельзя клонировать на другой ПК. Состояние подключения и выбранное поколение разделены по хешу Google sub. При входе заново требуется выбор способа подключения: новая учётная запись не получает предыдущую очередь автоматически.

Локальные настройки без версии получают начальную версию 0; облачная запись того же ключа имеет приоритет при первом объединении. История получает существующее время просмотра. Принятые записи сохраняют облачную версию и не создают эхо. Изменение во время сетевого запроса повторно захватывается под локальной блокировкой; изменение во время отправки оставляет pending.

Проверка поколений предотвращает автоматическое возвращение офлайн-данных после замены облака. Замена не удаляет старые файлы Drive: они исключаются поколением, сохраняя возможность технического восстановления. При очень большом числе устройств/поколений предусмотренные лимиты требуют ручного обслуживания; автоматическое удаление старых снимков не выполняется.

Обмен: при запуске/возвращении сети, каждые 60 секунд, переносимые настройки после 2 секунд, прогресс с ограничением 30 секунд, дополнительно пауза/выход из плеера. При закрытии локальная очередь завершается независимо от сети; последней отправке отводится до 3 секунд сетевого ожидания. Видеопозиция открытого плеера не меняется от облачного обновления, оформление откладывается до ухода с экрана плеера.

Секреты запрещены в DTO. Облачное хранение защищается аккаунтом Google; отдельного сквозного шифрования истории нет. Диагностика записывает тип ошибки, а не OAuth-ответы, названия или пути.
