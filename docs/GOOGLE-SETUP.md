# Google для PCinema 1.0

Эти шаги выполняет владелец PCinema один раз. Пользователи входят через общий Desktop OAuth-клиент; собственные Cloud-проекты им не нужны. Без клиента приложение работает локально.

## Настройка владельцем

1. В Google Cloud Console создайте проект PCinema и включите **Google Drive API**.
2. В Google Auth Platform заполните Branding: название, контакт поддержки, контакты разработчика. Для публичной поставки подготовьте домашнюю страницу и политику конфиденциальности с описанием хранения и удаления истории.
3. Audience: External. Пока приложение в Testing, добавьте тестовый Google-аккаунт в Test users.
4. Data Access: `openid`, `email`, `profile`, `https://www.googleapis.com/auth/drive.appdata`. Доступ к остальным файлам Drive не нужен.
5. Clients → Create client → **Desktop app**. Скачайте JSON. Web application и service account для этой реализации не подходят.
6. Сохраните JSON локально как `.secrets/google-oauth.json`. MSBuild скопирует его в сборку как `google-oauth.json`; файл исключён из Git. В готовой установке он находится рядом с `PCinema.exe`. Для разработки также поддерживается переменная `PCINEMA_GOOGLE_CLIENT_ID`, но скачанный Desktop JSON предпочтительнее.
7. Соберите приложение, откройте **Настройки → Аккаунт и синхронизация → Войти через Google**. Подтвердите аккаунт и разрешения в системном браузере. Выберите объединение, восстановление или замену облачной копии.

Desktop-клиент является публичным: его client ID и выданный Google client secret неизбежно доступны в установленном приложении. Это не пользовательский refresh token. PCinema использует PKCE S256, случайный state и временный callback `http://127.0.0.1:<случайный порт>/`. Пользовательский refresh token хранится отдельно под Windows DPAPI CurrentUser; он не попадает в пакет, журнал, SDK или снимки синхронизации.

## Публичная поставка

Переведите приложение из Testing в Production через Google Auth Platform. Проверьте требования Google к брендингу, доменам, политике конфиденциальности и верификации именно для выбранных scopes и вашей аудитории. `drive.appdata` является non-sensitive scope, но это не освобождает приложение от общих OAuth policies. Не обещайте отсутствие проверки или предупреждений до проверки статуса проекта в консоли. Внешние приложения в Testing могут получать refresh tokens с ограниченным сроком; этот режим не подходит для постоянной фоновой синхронизации пользователей.

Лучше иметь отдельные тестовый и production проекты. Данные appDataFolder связаны с приложением Google; смена проекта может потребовать повторного входа и не переносит старое хранилище автоматически.

Источники: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [скрытое хранилище Drive](https://developers.google.com/workspace/drive/api/guides/appdata), [OAuth policies](https://developers.google.com/identity/protocols/oauth2/policies).

## Проверка двух профилей

Используйте два отдельных каталога `PCINEMA_DATA_DIR` или два Windows-профиля. Не копируйте `installation.id`, Google-токены или базу между профилями. На одном компьютере запускайте профили последовательно: приложение использует single-instance защиту.

- Профиль A: добавить тестовую историю и настройки, войти, объединить, дождаться времени успешной синхронизации.
- Профиль B: войти тем же Google-аккаунтом, восстановить. Проверить историю без видео; вручную добавить соответствующую серию и проверить продолжение.
- Изменить позицию назад и настройки в A, синхронизировать B. Проверить офлайн-изменения и повторный вход.
- Проверить замену облака и явный выбор на старом профиле. Эта операция меняет только переносимые записи. До неё сохраняется резервная копия SQLite в `backups`.
- Отдельно проверить отмену браузерного входа, обновление access token, отзыв доступа в Google, выход и другой аккаунт.

Реальная интеграция считается проверенной только после успешного обмена через Google на двух профилях. Модульные тесты транспорта этого не заменяют.

## Данные и восстановление

Скрытая папка appDataFolder содержит версионированные JSON-снимки отдельных установок. Там нет видео, локальных путей, пакетов модулей, TMDB/Google-токенов или полного SQLite-файла. Выход удаляет локальный Google-токен; библиотека и облачные записи остаются. Данные Google-приложения можно удалить через управление подключёнными приложениями Google Drive.

Записи разрешаются по UTC-времени, логическому счётчику и ID установки. Новый просмотр, перемотка назад и сброс прогресса равноправны; максимальная позиция не выигрывает автоматически. При замене облака создаётся новое поколение, старый офлайн-профиль должен выбрать восстановление или объединение.
